# Bugs

这个目录只放真实缺陷，不放临时想法和待办清单。每个 bug 都应该能复现、能定位、能验证修复。

## 这里放什么

- 接口返回错误
- 状态机推进异常
- 前后端字段不一致
- 测试失败对应的真实问题

## 推荐结构

- `bug.md`：问题描述、复现步骤、根因、修复、验证

## 写作原则

- 先写复现，再写原因
- 先写影响范围，再写修复方式
- 修复后必须写验证结果
- 如果问题其实是 feature 未完成，不要伪装成 bug

## 当前仓库状态

- 目前仓库更像 scaffold 阶段，很多“缺失行为”不一定是 bug
- 只有真正偏离 PRD、API 契约或测试预期的情况，才应落到这里

## 状态建议

为了让缺陷修复也进入同一条测试和合并流水线，bug 记录默认复用 feature 状态：

`planned` -> `in_progress` -> `feature_test_passed` -> `merged_to_module` -> `closed`

如果后续需要单独的缺陷运营看板，可以在不破坏主状态流的前提下增加额外标签。
